# Завдання: веб-застосунок «Своя гра» (адмін-режим + режим гри)

Ти — senior full-stack розробник. Збудуй локальний веб-застосунок для проведення гри «Своя гра» на одному екрані (ноутбук → проєктор/ТВ). Ведучий керує всім через інтерфейс, команди відповідають усно. Працюй поетапно (див. розділ «Етапи»), після кожного етапу запускай застосунок і тести.

Мова інтерфейсу — **лише українська**. Мова коду, коментарів у коді — англійська; README — українською.

---

## 1. Стек і версії

- **Frontend:** React + **Vite** (шаблон `react-ts`), **TypeScript**, **CSS Modules + CSS custom properties** (теми через змінні). Без Next.js, без Tailwind.
- **Backend:** **Express 5** + TypeScript (Node.js).
- **Тести:** Vitest (unit-тести логіки балів/черги).
- **Зберігання:** JSON-файли та медіафайли на диску (без БД).
- **Версії (станом на жовтень 2026, перевір перед встановленням):**
  - Node.js: орієнтуйся на LTS — 24.x (Active LTS до 20.10.2026, далі Maintenance) або 26.x (входить в LTS 28.10.2026). У `package.json` вкажи `"engines": { "node": ">=24" }`.
  - React 19.2.x.
  - Express 5.x (з березня 2025 — `latest` на npm). Враховуй зміни Express 5: новий синтаксис wildcard-маршрутів (`/*splat`), нативна обробка помилок в async-хендлерах.
  - Vite — актуальна стабільна з `npm create vite@latest`.
  - **Перед закріпленням будь-якої залежності** виконай `npm view <pkg> version` і звір API з офіційною документацією (особливо: Express 5, бібліотека завантаження файлів, бібліотеки zip). Не покладайся на пам'ять щодо API.
- **Не замінюй** перелічені технології без явного погодження.

## 2. Структура репозиторію

npm workspaces, монорепо:

```
/client        React + Vite
/server        Express 5 API + роздача статики й медіа
/shared        TS-типи моделей + чиста логіка гри (бали, черга, валідація паку)
/data          (створюється автоматично, в .gitignore)
  /packs/<packId>/pack.json
  /packs/<packId>/media/<uuid>.<ext>
  /sessions/<sessionId>.json
```

- `npm start` — **одна команда**: збирає client і запускає server, який віддає фронтенд і API на `http://localhost:3000`, автоматично відкривати не обов'язково.
- `npm run dev` — паралельно Vite dev server (з proxy на API) + server у watch-режимі.
- `npm test` — Vitest для `/shared`.
- Сервер слухає `127.0.0.1`.
- **Усе має працювати офлайн** (на місці проведення може не бути інтернету): шрифти — локально через `@fontsource/*`, жодних CDN.

## 3. Модель даних (shared/types)

```ts
type MediaBlock =
  | { id: string; type: 'text'; text: string }
  | { id: string; type: 'image' | 'audio' | 'video'; file: string /* відносний шлях у media/ */; caption?: string };

interface AnswerOption { id: string; label: 'A' | 'B' | 'C' | 'D'; text: string }

interface Question {
  id: string;
  content: MediaBlock[];        // ≥1 блок; будь-які комбінації та порядок
  options: AnswerOption[];      // 0 або 2–4
  correctOptionId?: string;     // обов'язково, якщо options.length ≥ 2
  answer: MediaBlock[];         // ≥1 блок; екран правильної відповіді (теж комбіновані медіа)
}

interface Category {
  id: string;
  name: string;
  slots: (Question | null)[];   // рівно 5 слотів, відповідають стовпцям цін раунду; null = порожньо
}

interface Round {
  id: string;
  name?: string;                // напр. «Раунд 1»
  prices: [number, number, number, number, number]; // ціни стовпців, довільні додатні цілі
  categories: Category[];       // 1–5
}

interface Pack {
  id: string;
  title: string;                // показується дугою на стартовому екрані
  subtitle: string;             // за замовчуванням «від»
  logo?: string;                // файл у media/; якщо нема — дефолтний логотип ННІ ЕІТ
  status: 'draft' | 'ready';
  rounds: Round[];              // ≥1, без верхньої межі
  createdAt: string; updatedAt: string;
}
```

### Правила структури
- Раундів — будь-яка кількість (≥1).
- У раунді **від 1 до 5 категорій**; у категорії **до 5 питань** (≥1).
- Ціни задаються **на рівні стовпців раунду** (5 стовпців). Автопідстановка: `ціна[i] = (i+1) × 100 × номерРаунду` (раунд 1: 100–500, раунд 2: 200–1000, …), кожну можна змінити вручну.
- Порожній слот у сітці відображається як «—» і не клікабельний. Приклад: категорія має питання на 100, 200, 400, 500 → на місці 300 стоїть «—».
- Менше 5 категорій → у сітці менше рядків (рядки розтягуються на доступну висоту).

### Валідація для статусу `ready`
Пак можна позначити «готовим», лише якщо: є назва; ≥1 раунд; у кожному раунді 1–5 категорій з непорожніми назвами; у кожній категорії ≥1 питання; кожне питання має ≥1 блок контенту і ≥1 блок відповіді; варіантів 0 або 2–4, і при їх наявності позначено правильний; всі ціни — додатні цілі; всі медіафайли існують. Валідатор — у `/shared`, повертає список помилок з «адресою» (раунд/категорія/слот), щоб в адмінці можна було перейти до проблемного місця. При збереженні `ready`-паку, який перестав бути валідним, — він повертається в `draft` з попередженням.

## 4. API (Express 5)

Мінімальний набір (можеш уточнити, але збережи суть):
- `GET /api/packs` — список (id, title, status, к-сть раундів, updatedAt).
- `GET /api/packs/:id`, `POST /api/packs`, `PUT /api/packs/:id`, `DELETE /api/packs/:id`, `POST /api/packs/:id/duplicate`.
- `POST /api/packs/:id/media` — завантаження файлу (multipart). Файл зберігається як `<uuid>.<ext>` у `data/packs/<id>/media/`, повертається відносний шлях. Ліміт **500 МБ** на файл. Дозволені формати: зображення `jpg, jpeg, png, webp, gif`; аудіо `mp3, ogg, wav`; відео `mp4, webm`. Перевіряй розширення і MIME.
- `GET /media/:packId/*` — роздача медіа з підтримкою **HTTP Range** (перемотування відео/аудіо).
- `GET /api/packs/:id/export` — `.zip` (pack.json + media/).
- `POST /api/packs/import` — імпорт `.zip`; при конфлікті id — новий id; захист від zip-slip; валідація структури.
- При збереженні паку видаляй медіафайли, на які більше немає посилань.
- `GET /api/sessions/active`, `POST /api/sessions`, `PUT /api/sessions/:id`, `DELETE /api/sessions/:id`.
- Запис JSON — **атомарно** (запис у тимчасовий файл + rename), щоб краш не зіпсував файл.

## 5. Головний екран

- Стилізований (див. «Дизайн»), маскот-кіт.
- Дві великі кнопки: **«Гра»** і **«Адмін»**. Без логіна/паролю.
- Перемикач теми (темна/світла) і кнопка повноекранного режиму.

## 6. Адмін-режим (нейтральний стиль)

Нейтральний, функціональний інтерфейс (світлий, мінімалістичний), лише акцентні кольори бренду. Повноекранний режим не потрібен.

- **Список паків:** назва, статус (бейдж «Чернетка»/«Готовий»), дата зміни; дії: відкрити, дублювати, видалити (з підтвердженням), експорт .zip; кнопки «Новий пак», «Імпорт .zip».
- **Редактор паку:**
  - Метадані: назва, підзаголовок (дефолт «від»), логотип (завантаження; дефолт — логотип ННІ ЕІТ).
  - Раунди: додати/видалити/перевпорядкувати; назва раунду; 5 полів цін (з автопідстановкою).
  - Категорії раунду: 1–5, додати/видалити/перевпорядкувати, назва.
  - Сітка-прев'ю раунду (як у грі, спрощено): клік по слоту → редактор питання; порожні слоти позначені.
  - **Редактор питання:**
    - Контент питання: список блоків (Текст / Картинка / Аудіо / Відео), можна додавати кілька будь-яких, перевпорядковувати, видаляти; прев'ю медіа.
    - Варіанти відповіді: перемикач «без варіантів / з варіантами»; 2–4 варіанти з мітками A–D; позначка правильного.
    - Правильна відповідь: такий самий список блоків (текст/медіа, комбіновано).
    - Кнопка «Очистити слот».
  - Явна кнопка **«Зберегти»** + попередження про незбережені зміни при виході.
  - Кнопка **«Позначити готовим»** → запуск валідації → або статус `ready`, або список помилок з переходом до місця помилки.
  - Пак, по якому є незавершена ігрова сесія, — показувати попередження при редагуванні.

## 7. Режим гри (повноекранний, стилізований)

Увесь екран бачать гравці. Керування ведучого — ненав'язлива панель/кнопки (невеликі, у стилі гри; можна автоховання панелі при неактивності миші), усе працює мишею і гарячими клавішами.

### 7.1 Вхід
- Якщо є незавершена сесія → діалог: **«Продовжити гру „<назва паку>“»** / **«Нова гра»** (нова — архівує/видаляє стару після підтвердження).
- Вибір паку: показуються **лише паки зі статусом `ready`**.

### 7.2 Стартовий екран паку
- Як на референсі: назва паку **по дузі** (SVG `textPath`, шрифт масштабується під довжину назви), під нею підзаголовок («від») і логотип паку. Маскот.
- Кнопка «Почати».

### 7.3 Додавання команд
- 2–8 команд, лише назви (непорожні, унікальні, до ~30 символів). Додати/видалити/перевпорядкувати.
- Кнопка «Старт» → **анімація випадкового вибору першої команди** (рулетка: підсвітка біжить по назвах із уповільненням ~3 с, зупиняється на обраній).
- Черга: порядок додавання, старт з випадкової команди, далі **строго по колу**.

### 7.4 Ігрове поле
- Сітка як на референсі: зліва назви категорій, далі стовпці цін раунду. Порожній слот — «—». Зіграні клітинки — візуально приглушені/порожні, некликабельні.
- Над/біля сітки — назва раунду.
- **Знизу — табло команд:** назва + бали, **виділена команда, чия зараз черга**. До 8 команд — в один ряд, за потреби у 2 ряди.
- Ведучий може **приховати рахунок** (кнопка/гаряча клавіша): замість балів «???», назви лишаються. Повторне натискання — показати.
- Ведучий може **вручну змінити бали** будь-якої команди: діалог з +/− довільної суми.

### 7.5 Екран питання (клік по клітинці)
- Анімація розкриття клітинки на весь екран.
- Показується: категорія, ціна, команда, чия черга, контент питання (усі блоки). Аудіо/відео — **лише ручний запуск** (кнопки ▶/⏸/повтор, без автоплею). Якщо є варіанти — показувати A–D одразу разом із питанням.
- Кнопки ведучого: **✅ Правильно**, **❌ Неправильно**, **«Закрити без нарахування»**.
  - «Закрити без нарахування» доступна лише до першого ✅/❌ у цьому питанні; клітинка лишається доступною, черга не змінюється.

### 7.6 Логіка відповіді та перехоплення
1. ✅ для команди черги → `+ціна` → екран відповіді.
2. ❌ для команди черги → `−floor(ціна/2)` → панель **«Перехоплення»** (правильна відповідь **ще прихована**):
   - Список інших команд, у кожної ✅ і ❌.
   - ❌ → ця команда `−floor(ціна/2)`, стає неактивною для цього питання.
   - ✅ → ця команда `+ціна`, перехоплення завершується.
   - **«Ніхто»** → завершити без нарахувань.
   - Якщо всі інші команди отримали ❌ — перехоплення завершується автоматично.
3. Далі — **екран правильної відповіді**: усі блоки відповіді (комбіновані медіа, ручний запуск), якщо є варіанти — підсвічений правильний.
4. Кнопка «До поля» → клітинка закривається → черга переходить до **наступної команди після команди черги** (перехоплення на коло не впливає).

Округлення штрафу — **вниз до цілого**: 125 → −62, 150 → −75. Рахунок **може бути від'ємним**.

### 7.7 Раунди та фінал
- Коли всі непорожні клітинки раунду зіграні → з'являється кнопка **«Наступний раунд»**. Також ведучий може перейти до наступного раунду **будь-коли** (з підтвердженням).
- Перехід — коротка заставка «Раунд N: <назва>». Бали й черга (коло) **переносяться** між раундами.
- Після останнього раунду — **екран переможця з підсумковою таблицею** (місця, назви, бали; однакові бали — спільне місце), маскот, анімація.

### 7.8 Збереження стану
- Після **кожної дії** (нарахування, зміна черги, закриття клітинки, ручна зміна балів, перехід раунду, приховування рахунку) стан сесії записується на сервер у `data/sessions/<sessionId>.json` (перезапис, атомарно).
- Стан: packId, команди й бали, порядок і поточний індекс черги, поточний раунд, зіграні клітинки, поточний екран/питання й прогрес перехоплення, прапорець прихованого рахунку, статус (активна/завершена).
- F5 / закриття браузера посеред гри → після повернення гра відновлюється з того самого місця.

### 7.9 Гарячі клавіші (режим гри)
Не перехоплювати, коли фокус у полі вводу.
- `F` — повноекранний режим вкл/вимк (Fullscreen API).
- `H` — приховати/показати рахунок.
- `T` — перемкнути тему.
- `Space` — ▶/⏸ поточного медіа.
- `Esc` — закрити відкритий діалог (не скасовує нарахувань).
- На панелі перехоплення: `1`–`8` — обрати команду (показати підказки).
- Показати шпаргалку клавіш (`?`).

## 8. Дизайн

Референси (надам окремо): ігрове поле — сітка з білими розділювачами, великі жовті цифри, широкий гротеск; стартовий екран — назва дугою, «від», логотип ННІ ЕІТ (жовтий, з символом «power» замість літери). Маскот — кіт у шапці, шарфі та светрі з символом power і написом «EiT», лінійна графіка.

- **Теми через CSS-змінні**, перемикання без перезавантаження, вибір запам'ятовується (localStorage з try/catch):
  - **A — темна (за замовчуванням):** майже чорний фон, жовтий акцент (~`#F7E36B`) для цифр і назв, білі/світлі лінії сітки, кіт світлими лініями.
  - **B — світла (для яскравого освітлення):** сіро-бежевий фон, темно-коричневі лінії й текст (як у маскота), акцент — насичений жовто-гірчичний з достатнім контрастом.
  - Контраст тексту ≥ WCAG AA на обох темах (читається з проєктора).
- **Фон:** однотонний з **легким візерунком із котячих елементів** (вушка, лапки) — тонкі лінійні SVG-іконки, які ти малюєш сам, низька прозорість (~4–8%), не відволікає. Один і той самий фон на всіх екранах гри (включно зі стартовим).
- **Шрифти:** **Unbounded** — заголовки, назви категорій, цифри; **Manrope** — текст питань і інтерфейс. Обидва з кирилицею, підключити локально (`@fontsource`).
- **Маскот на всіх екранах гри** (головний, старт паку, команди, поле, питання, відповідь, фінал) — у ненав'язливій позиції, не перекриває контент. Поки немає фінальних файлів — заглушки. Шляхи: `client/public/brand/cat.(svg|png)`, `client/public/brand/logo.(svg|png)`; зроби компонент так, щоб пізніше легко додати варіанти кота (напр. радісний/сумний для правильної/неправильної відповіді). Для SVG-кота колір ліній — через `currentColor`, щоб він адаптувався до теми.
- **Анімації (так, звуків — ні):** розкриття клітинки, приглушення зіграної клітинки, плавна зміна балів (count-up/down), поява панелі перехоплення, рулетка вибору першої команди, заставка раунду, фінальний екран. Тривалість 200–500 мс (рулетка ~3 с). Повага до `prefers-reduced-motion`.
- **Адаптивність:** гра має масштабуватися під будь-який екран (від 1280×720 до 4K, 16:9 і 16:10) через `clamp()`/vw/vh, без горизонтального скролу; основний пристрій зараз — **MacBook Air M2, Chrome**. Має працювати в Chrome/Edge/Firefox/Safari, на macOS і Windows.
- Мінімалістично: без декоративного «шуму», чисті лінії.

## 9. Тести (Vitest, `/shared`)

Логіка балів і черги — чисті функції в `/shared`, покриті тестами:
- правильна відповідь команди черги: `+ціна`;
- неправильна: `−floor(ціна/2)`, у т.ч. непарні ціни (125 → −62, 150 → −75);
- перехоплення: кілька ❌ з штрафами + один ✅ з повною ціною; «Ніхто»; автозавершення, коли всі ❌;
- рахунок іде в мінус;
- черга після перехоплення переходить до наступного після команди черги;
- «Закрити без нарахування» не змінює черги й балів;
- кінець раунду = усі непорожні клітинки зіграні;
- ранжування фіналу зі спільними місцями;
- валідатор паку (позитивні та негативні кейси).

Приклад-сценарій: команди «Сухарики», «Чипси», «Бекон», черга «Сухариків», питання 100. «Сухарики» ❌ → −50; «Чипси» ✅ → +100; далі ходять «Чипси» (наступні після «Сухариків»).

## 10. Етапи та критерії готовності

1. **Каркас:** монорепо, `npm start`/`npm run dev`/`npm test`, Express віддає SPA, теми, шрифти, головний екран.
2. **Shared:** типи, валідатор, логіка балів/черги + тести (зелені).
3. **Адмінка:** CRUD паків, редактор раундів/категорій/питань, завантаження медіа, статуси, експорт/імпорт .zip.
4. **Гра:** вибір паку, стартовий екран з дугою, команди + рулетка, поле, питання, перехоплення, відповідь, раунди, фінал.
5. **Стан і керування:** автозбереження сесії, відновлення після F5, діалог «Продовжити/Нова гра», ручна зміна балів, приховування рахунку, гарячі клавіші, повноекранний режим.
6. **Полірування:** анімації, адаптивність, візерунок фону, заглушки маскота, README.

Додай **демо-пак** (2 раунди, з текстом, картинкою, аудіо/відео-заглушками, порожнім слотом і питанням з варіантами), щоб одразу перевірити всі сценарії.

**Готово, коли:** `npm start` піднімає застосунок з нуля після `npm install`; демо-пак проходиться повністю від старту до фіналу; F5 посеред питання відновлює стан; експорт → імпорт паку на «чистій» папці `data/` працює з медіа; усі тести зелені; немає помилок у консолі браузера.

## 11. ASSUMPTIONS (прийняті за замовчуванням)

- Ціни задаються на рівні стовпців раунду, а не окремо для кожного питання.
- «Закрити без нарахування» — лише до першого ✅/❌.
- Ведучий оцінює відповідь вручну навіть за наявності варіантів (автоперевірки немає).
- Перехоплення завершується автоматично, коли всі інші команди отримали ❌.
- Між раундами — коротка заставка; бали й коло черги переносяться.
- Видалення невикористаних медіа — при збереженні паку.
- Сервер доступний лише з `127.0.0.1`.

## 12. Поза межами v1

Спецпитання («Кіт у мішку», «Аукціон»), таймер відповіді, звуки, мультимовність, логін, мультипристрійна гра (телефони команд), фінальний раунд зі ставками.
